파일럿 문의

지금 상태: 초대제 파일럿 준비 중

흩어진 맥락을
한 매듭으로

Claude Code 같은 코딩 에이전트로 혼자 만드는 분을 위한 프로젝트 지도와 진행 기록이에요.

GitHub 저장소를 한 번 연결하면, 에이전트는 MCP(코딩 에이전트가 바깥 도구를 부르는 연결 방식)로 프로젝트 지도를 읽어요. 에이전트가 무엇을 읽고 어디까지 했는지는 관측소, 지도, 진행 화면에서 봐요. 원본 코드는 저장하지 않아요.

파일럿 문의 데모 보기

데모는 예시 데이터로 움직여요. 그 안의 ‘내 저장소 연결’은 초대받은 분만 눌러 주세요.

무엇을 하나요

두 가지를 한 매듭으로 묶어요. 하나는 사람이 보는 프로젝트 진행, 하나는 코딩 에이전트가 읽는 저장소 지도예요.

첫째 끈

프로젝트 진행

저장소마다 관측소가 하나씩 생겨요. 관측소는 저장소를 열면 처음 보이는 화면이에요. 저장소를 둘 이상 연결하면 홈에 저장소마다 카드가 한 장씩 놓여요. 어디까지 왔고 무엇이 남았는지 봐요. 숫자는 모두 저장된 기록에서 나와요.

진행
카드와 관측소에는 완료 3/10처럼 센 개수를 적어요. 세어 볼 근거가 없으면 0%가 아니라 미측정이라고 적어요. 진행 화면의 지표 카드에는 아직 퍼센트도 함께 나와요.
할 일
TODO 문서의 체크박스와 에이전트가 남긴 진행 기록에서 모아요. 7일 넘게 멈춘 일과 막힌 일은 따로 보여 줘요.
그동안의
변화
오늘, 최근 7일, 마지막으로 연 뒤에 생긴 진행과 commit, 해소된 문제를 세어요.
먼저 볼
파일
같이 바뀌는 파일, 열린 문제, 테스트 없음 같은 요인이 겹친 파일부터 줄 세워요.
보안
package-lock 같은 잠금 파일에 적힌 패키지를 OSV.dev에 물어본 결과를 보여 줘요. 묻지 못한 곳은 미측정이나 부분 측정으로 남겨요.

둘째 끈

저장소 지도

저장소를 별지도로 그려요. 파일은 별, 영역은 별자리예요. 코딩 에이전트는 MCP로 이 지도에 물어 경로와 심볼, 이어진 파일을 받아요. 메모와 진행 기록을 남기는 도구도 있어요. 다음 세션이나 다른 에이전트가 그 기록을 이어 읽는지는 파일럿에서 함께 확인해요.

별자리
영역이에요. 프론트엔드, 백엔드, 데이터베이스, 문서, 테스트, 기타로 나눠요.
밝기
중요도예요. 다른 파일이 많이 기대는 파일일수록 밝아요.
별표
아래 예시에서 에이전트가 물은 파일이에요.

al-rishā’Alrescha는 ‘끈’을 뜻하는 아랍어 al-rishā’에서 온 이름이에요. 물고기자리에서 두 물고기를 잇는 끈이 이 별에서 만나 매듭이 돼요. 제품도 두 끈을 한 매듭으로 묶어요.

지금 할 수 있는 일

지금 앱에 들어 있는 화면과 에이전트 도구예요. 몇몇은 배포만 됐고 아직 운영에서 확인하지 않아서 ‘운영 확인 전’이라고 적었어요. 지금까지는 만든 사람의 계정 하나로만 운영해 봤어요. 다른 분의 저장소에서는 파일럿에서 처음 확인해요.

앱 화면

사람이 보는 곳

관측소
저장소를 열면 처음 보이는 화면이에요. 파일을 별지도로 그리고, 할 일, 먼저 볼 파일, 보안, 에이전트 기록, 마지막 스캔이 얼마나 지났는지를 옆에 모아요./app/r/<owner>/<name>
프로젝트 카드
저장소를 둘 이상 연결하면 홈에 저장소마다 카드가 한 장씩 놓여요. 마지막 스캔, 할 일, 열린 문제, 보안, 에이전트 기록을 저장된 기록 그대로 적어요. 저장소가 하나면 홈 대신 관측소가 바로 열려요./app
지도
파일, 문서, 요구사항이 서로 어떻게 이어지는지 그래프로 펼쳐요. 앱의 탭 이름은 Graph예요. 영역과 증거 등급으로 걸러 보는 기능은 아직 운영에서 확인하지 않았어요.…/map
진행
출처가 있는 할 일만 모아요. 출처는 문서의 경로와 줄, 또는 에이전트가 남긴 진행 기록이에요.…/progress
프로젝트 점검운영 확인 전
규칙이 찾은 문제와 의존성 검사 결과를 한곳에 모아요. spec이나 ADR 같은 설계 문서가 없는 저장소에서는 문서와 코드가 어긋난 곳을 찾지 못하고, 테스트 없는 파일 위주로 표시돼요.…/inspection
영수증운영 확인 전
분석한 commit마다 무엇을 근거로 봤는지 기록을 남겨요. 나중에 그 기록이 바뀌었는지 서버가 다시 계산해 확인하고, 기록이 다룬 파일이 그 뒤에 바뀌면 표시해요. 앱의 탭 이름은 Receipts예요. 아직 서명은 없어요.in-toto Statement · SHA-256 digest · …/receipts

MCP 도구

에이전트가 쓰는 곳

연결운영 확인 전
설정의 MCP 접근 화면에서 토큰을 만들고, 에이전트에게 줄 지시 블록과 연결 설정을 복사해 붙여요. 연결 설정은 지금 모든 클라이언트에 같은 JSON 하나이고, Codex용 설정(config.toml)은 아직 없어요. Codex와 Cursor는 운영에 연결해 본 적이 없어서 파일럿에서 처음 확인해요./app/settings/mcp
토큰운영 확인 전
조회만 하는 토큰은 90일, 기록 권한이 있는 토큰은 30일 뒤에 만료돼요. 만료가 다가오면 설정 화면이 알려 줘요.mcp:read · mcp:write
찾기
에이전트가 물으면 파일 경로, 심볼과 줄 범위, 이어진 파일, 바꾸면 영향이 닿는 곳을 돌려줘요. 원본 코드는 답에 싣지 않아요.search_index · get_artifact · get_neighbors · impact_of
문제
규칙이 찾은 문제(Findings)를 근거 위치와 함께 돌려줘요.get_findings
기억과 진행운영 확인 전
에이전트가 메모와 진행 기록을 남기고 읽는 도구예요. 진행 기록은 진행 화면과 관측소에 보여요. 지금 설정 화면의 지시 블록에는 진행 기록을 남기라는 말이 없어서, 에이전트에게 따로 알려 줘야 해요. 기억은 저장소가 아니라 워크스페이스 단위라서, 다른 저장소에서 남긴 기억도 함께 읽혀요.memory_read · memory_write · log_progress

지금은 찾기와 문제의 답이 너무 커서, 에이전트 쪽에서 경고가 뜨거나 답이 잘릴 수 있어요. 파일럿 전에 답 하나의 크기에 상한을 둘 예정이에요.

에이전트가 읽는 순간

에이전트가 MCP로 물으면, Alrescha는 스캔해 둔 지도에서 답을 찾아 파일 경로와 줄 범위를 돌려줘요. 아래는 Alrescha 자기 저장소에 물어본 예시예요.

  1. 에이전트가 묻고

    작업하던 코딩 에이전트가 Alrescha MCP에 질문을 보내요.

    search_index({ query: "brain area" })

  2. 지도에서 찾고

    질문에 맞는 파일과 심볼, 그 파일에 이어진 파일을 골라요. 그림의 별표가 이 질문에 걸린 파일이에요.

    packages/core/src/ingest/artifact-facets.ts

  3. 근거를 받아요

    에이전트는 경로와 줄 범위를 받아, 자기 작업 공간에서 그 자리를 바로 열 수 있어요. 원본 코드는 답에 실리지 않아요.

    type     BrainArea         263–264
const    BRAIN_AREAS       266–273
function deriveBrainArea   275–288

응답을 줄여 옮긴 예시예요. 실제 답은 이보다 훨씬 길어요. 줄 번호는 2026년 9월 29일 Alrescha 저장소 기준이에요. 에이전트가 어떤 도구로 어떤 파일을 읽었는지는 접근 기록으로 30일 동안 남고, 관측소에서 마지막 읽기를 볼 수 있어요. 질문한 글은 접근 기록에 남지 않아요.

지키는 약속

아래는 요약이에요. 자세한 개인정보 안내는 파일럿을 시작하기 전에 따로 드려요.

  • ‘확인됨’은 실행 증거에만

    GitHub Actions에서 돌린 테스트 결과에서 실제로 통과한 테스트 파일만 확인됨(verified)으로 올려요. 규칙이 찾은 문제는 모두 추정(inferred)이에요.

    지금 영수증 화면의 ‘구현 verified’는 이 원칙과 어긋나요. 이름 일치와 체크 표시로 센 값이에요. 진행 화면은 같은 값을 ‘구현 체크됨’이라고 불러요.

  • 원본 코드는 저장하지 않아요

    스캔하는 동안만 읽고 버려요. 남는 건 경로, digest, 심볼 이름과 줄 위치, 파일 사이의 연결이에요. 짧은 글은 저장해요. 요구사항 문장, 체크박스 제목, ID가 붙은 제목줄, WHY:와 NOTE: 주석, 문제의 제목, 의존성 권고의 요약이에요. 직접 ‘라이브러리에 저장’을 누른 지시문 파일만 본문을 저장해요.

    로그인한 GitHub 계정의 이메일과 신원도 저장해요. 기록은 서울에 두고, 분석 작업은 도쿄의 서버에서 해요. 잠금 파일의 패키지 이름과 버전은 OSV.dev(미국)에 보내요. 에이전트가 쓴 기록은 기한 없이 남고, 기억은 지우지 않고 무효로만 표시해요.

  • 파일럿 지표는 동의한 뒤에만

    에이전트의 MCP 호출 기록은 동의와 상관없이 30일 동안 남아요. 이 기록으로 만드는 통계와 주간 파일럿 지표 파일은 계정 주인이 통계 화면에서 동의해야 열려요. 주간 파일은 2026년 10월 24일부터 받을 수 있고, 계정 주인이 직접 내려받아 운영자에게 건네요. 소스 코드, 파일 경로, 저장소 이름은 넣지 않아요.

    주간 파일에는 동의 전 기록 일부(연결 이정표, 실패 횟수)도 들어가요. 동의를 끄면 바로 멈추지만, 이미 쌓인 기록은 지우지 않아요.

  • 재지 않은 숫자는 말하지 않아요

    토큰이 얼마나 줄었는지, 정확도가 얼마나 올랐는지는 측정한 뒤에 가정과 함께 말해요. 이 페이지에 효율 수치가 없는 이유예요.

  • 아직 약속하지 않는 것

    • 토큰 절감과 정확도 향상. 미리 정해 둔 벤치마크에서 아직 기준을 넘지 못했어요.
    • spec이나 ADR 같은 설계 문서가 없는 저장소에서 문서와 코드가 어긋난 곳을 찾는 일.
    • AI가 쓴 요약과 문서 발췌. 앱에 AI 버튼이 아직 보이지만, 파일럿에서는 AI 기능을 쓰지 않아요.
    • 에이전트가 읽을 때 지도의 별이 실시간으로 반짝이는 표시.

초대제 파일럿을
준비하고 있어요

지금까지는 만든 사람의 계정 하나로만 운영해 봤어요. 파일럿에서는 초대한 분의 GitHub 저장소로 연결, 첫 스캔, 에이전트 연결까지 함께 확인해요. Claude Code로 만들고 있는 저장소면 좋아요. Codex 연결은 파일럿에서 함께 확인해요.

시작하기 전에 짧은 파일럿 동의서와 개인정보 안내를 먼저 보내 드려요. 파일럿은 무료이고, AI 기능은 쓰지 않아요. 서비스가 늘 돌아간다고 약속하지 않아요. 어느 쪽이든 언제든 그만둘 수 있고, 끝나면 운영자가 가진 기록을 지워요. 가격은 아직 정하지 않았어요.

파일럿 문의는 GitHub 이슈로 남겨 주세요. 이슈는 누구나 볼 수 있으니 이메일 같은 연락처나 저장소 이름은 적지 말아 주세요. 이야기가 되면 이슈에 운영자 메일 주소를 알려 드리고, 그다음은 메일로 이어 가요. 처음에는 몇 분만 모셔요.

GitHub 이슈로 문의 데모 보기

이슈 양식은 쓰는 에이전트, 언어나 스택, 보고 싶은 것을 물어요.

데모는 예시 데이터로 움직여요. 실제 계정이나 저장소를 읽지 않고, 앱에 아직 없는 화면도 있어요. 데모 안의 ‘내 저장소 연결’과 ‘앱 열기’는 아직 열려 있지 않아요. 누르면 GitHub 로그인으로 넘어가니, 초대를 받기 전에는 누르지 말아 주세요.
